# 시스템 명세 — 투자신청서 점검·회의자료 에이전트

업무 규칙(흐름·양식·검토 기준·매칭 규칙·정답셋·관리 방법)은 `CLAUDE.md` 「업무 규칙」이 기준이다.
이 문서는 그 규칙을 **누가(에이전트·스크립트·사람) 어떤 권한으로** 처리하는지 정한다.

## 1. 범위

| 업무 단계 (CLAUDE.md §1) | 변경 후 | 담당 |
|---|---|---|
| 투자접수 | 그대로 (신청서 pptx 접수 → `inbox/`) | 사람 |
| 투자검토 | 에이전트가 신청서 점검, 검토 필요 사항을 검토자에게 제공 | invest-reviewer (+ invest-standardize 스킬) |
| 투자회의 | 계획 변경 사항을 반영한 요약 표지 + 자료 준비 | invest-meeting |

## 2. 역할·도구 권한 (에이전트 설계)

원칙: **판단하는 쪽과 쓰는 쪽을 나눈다.** 숫자·존재 여부 규칙은 스크립트가 확정하고, 에이전트는 서술을 읽어야 하는 판단만 한다. 원본은 아무도 쓰지 않는다.

| 구성 요소 | 역할 | 입력 | 출력 | 도구 권한 | 할 수 없는 것 |
|---|---|---|---|---|---|
| **invest-reviewer** (에이전트) | 신청서 점검, 잘못된 점 설명, 통과 건 전달 | `inbox/*.pptx` | `out/검토결과.html·xlsx`, `out/review/*.json`, `out/표준화/*` | Read, Glob, Grep, Bash | Write·Edit 없음 / 원본 수정(훅 차단) / 스크립트 판정 변경(`judge` 거부) / 검토자 O 표시 |
| **invest-meeting** (에이전트) | 상정 건으로 회의자료·브리핑 작성 | `out/검토결과.xlsx` 의 상정 건, `data/` | `out/투자회의자료_*.html` (+ 출력용 .pptx), `out/회의_요약.xlsx`, `out/회의_브리핑.md` | Read, Glob, Grep, Bash, Write | Edit 없음 / 상정 조건 우회 / 표지 숫자 수정 / 원본 수정(훅 차단) |
| **invest-standardize** (스킬) | 다른 양식 → 표준양식 (양식만) | 다른 양식 pptx | 변환본 + 검증 기록 | (호출한 에이전트의 권한) | 내용 수정 — 추가·누락 있으면 검증 실패 |
| 스크립트 (`scripts/`) | 규칙 판정·매칭·문서 생성 (확정적) | — | — | — | — |
| **사람 (검토자)** | 판단 필요 항목 승인, 원본 수정, 기준값 확정 | HTML·엑셀 | 엑셀 검토자 확인 O | 모두 | — |

reviewer 에 Write 가 없는 이유: 판정은 `review.py judge`, 매핑 JSON 은 Bash heredoc 으로만 남기게 해서 **파일을 직접 만들 수 있는 경로를 줄였다** (`tests/test_safety.py::test_에이전트_도구_권한_분리` 가 확인).

## 3. 처리 흐름과 데이터 계약

```
inbox/X.pptx
  ├─ 표준양식?  아니오 → standardize dump → (에이전트) 매핑 JSON → standardize build
  │                         out/표준화/X.pptx + X.json {원본경로, 원본해시, 추가[], 누락[], 왕복불일치[], 통과}
  ▼
review.py check  (인자 없이: 표준양식 원본 + 검증 통과 변환본)
  out/extract/X.json   신청서에서 읽은 값 {투자명, 투자효과, 상세{…}, 부가{항목: 글}, 견적[], 원본해시, 변환원본?}
  out/review/X.json    {신청서ID, 경로, 원본해시, 변환원본, rows[{규칙ID, 판정, 근거, 보완요청문구, AI대기, 검토자확인}]}
review.py pending → (에이전트) review.py judge  : AI대기 행만 판정 가능
review.py report → out/검토결과.html (설명 화면) + out/검토결과.xlsx (① 상세 ② 요약 ③ 보완·확인)
  ▼ 사람: ① 의 판단 필요 행에 검토자 확인 = O
meeting.py  → 상정 = 보완 0 + AI대기 0 + 판단 필요 전부 O  (R-401)
            → 원본 지문이 점검 때와 같을 때만 (변환본이면 변환 원본까지)
            → match.py 로 경영계획·집행이력 대조 (M-0~M-9) → pptx·xlsx
```

판정 값: `충족 / 보완 / 판단 필요 / 해당 없음`. 종합 상태: 보완 1건 이상 → 보완 요청 / 판단 필요 0·AI대기 0 → 검토 통과 / 그 외 → 검토자 확인 필요.

## 4. 규칙 (요약 — 전체 조건은 CLAUDE.md §3·§5)

| ID | 내용 | 판정 주체 |
|---|---|---|
| R-100 | 표준양식, 또는 검증 통과한 변환본 | 스크립트 |
| R-101~R-105 | 투자명·수량·유형·금액·견적서 | 스크립트 |
| R-102 | 현수량/필요수량/투자수량. 노후교체: 투자 ≤ 필요 / 그 외: 투자 ≤ 필요 − 현 | 스크립트 |
| R-106·R-107 | 최저가 원칙. 업력 5년 미만 신생 업체는 최저가여도 미선정(선정하면 보완). 미선정 사유 없으면 예시 문구 제시 | 스크립트 |
| R-108 | 투자경과 = 투자 시작 후 걸리는 개월 수 | 스크립트 |
| R-201 | 기재 유형과 투자효과 내용이 맞는가 | **에이전트** |
| R-202·R-203 | 부 유형, 유형별 필수 부가 항목 | 스크립트 |
| R-301 | 필요성 서술이 있는가 | **에이전트** |
| R-302·R-311~R-314·R-321 | 부하·조업도 / 운용연수·교체 수량·사유·노후 수량 / 금액·JMH·인력 감소 | 스크립트 |
| R-322 | 효과 산출식 재계산·회수기간 | **에이전트** |
| R-401 | 회의 상정 조건 | 스크립트 + **사람(O)** |
| M-0~M-9 | 계획 NO 대조, 위치·수량·유형 변경, 계획 外·초과·분할·미신청 | 스크립트 (정답셋 T1~T6) |

수치 기준은 `config/기준값.json`. `[확정 필요]` 표시는 동료 합의 전 임시값이다.

## 5. 안전장치 (규칙 + 훅)

| 위험 | 막는 방법 | 층 |
|---|---|---|
| 에이전트가 신청서·경영계획·기준 문서를 고침 | 권한 deny `Edit(./inbox/**)` 등 + `guard.py` (Write/Edit/셸 rm·mv·cp·리다이렉트·`.save()`·변환 스크립트) → **에이전트는 차단** | 예방 |
| 대화 중 Claude 가 원본을 고침 | `guard.py` → **사용자 승인 요청(ask)** — 사용자가 요청한 수정만 승인 | 사람 확인 |
| 사용자가 오류를 넣은 inbox 를 샘플로 덮어씀 | `make_samples.py` 기존 파일 보존 + `--force` 는 훅이 차단 (사용자가 `!` 로만) | 예방 |
| 훅을 피한 경로로 원본이 바뀜 | `inbox_watch.py` 가 에이전트 시작·종료 시 SHA-256 비교 → 경고 | 감지 |
| 점검 뒤 바뀐 신청서가 회의에 들어감 | `meeting.py` 원본 지문 대조 → '재점검 필요' 보류 | 감지 |
| 에이전트가 규칙 판정을 뒤집음 | `review.py judge` 가 AI대기 행 외에는 거부 | 예방 |
| 변환하며 내용이 바뀜 | `standardize.py` 추가·누락·왕복 검증, 실패 시 점검 대상 제외(R-100 보완) | 예방 |
| 비밀 값 커밋 | `guard.py` 가 키·토큰·비밀번호 형태 쓰기 차단, `.gitignore`(.env, out, 백업), `test_저장소에_비밀값_없음` | 예방·감지 |
| 되돌릴 수 없는 명령 | `guard.py`·deny: force push, reset --hard, clean -f, 루트·프로젝트 재귀 삭제 | 예방 |

한계 (정직하게): 셸 명령 검사는 문자열 기반이라 간접 경로(임의 스크립트 안의 저장)는 예방하지 못한다 → `inbox_watch.py`·`meeting.py` 의 지문 대조로 사후 감지한다. 백그라운드 작업 세션은 훅 입력에 에이전트로 표시되어, 대화형 승인 대신 차단된다(이때 원본 수정은 사용자가 터미널에서 직접 실행).

## 6. 사람이 확인하는 지점

| 지점 | 무엇을 | 왜 사람인가 |
|---|---|---|
| 오류 주입·신청서 수정 | inbox 신청서 내용 | 원본은 신청자 책임. 에이전트가 고치면 점검이 무의미 |
| 판단 필요 승인 (엑셀 O) | R-201 유형 불일치, 회수기간 근거 등 | 서술 해석·예외 인정은 책임 있는 사람이 결정 (R-401) |
| 원본 수정 승인 (훅 ask) | Claude 의 원본 쓰기 | 요청한 수정인지 사람만 안다 |
| 기준값 확정 | `config/기준값.json` 의 [확정 필요] | 조직 합의 사항 (CLAUDE.md §8 기준 제공자·이견·변경 이력) |
| 변환 경계 사례 | 원문에 칸이 애매한 값 (예: "견적 2곳 비교" → 견적 수) | 원문 보존 vs 칸 채우기 판단 |
| 회의 결정 | 계획 外·초과·유형 변경 (표지 '확인 필요') | 투자 결정은 회의체 권한 |
