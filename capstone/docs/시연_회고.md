# 시연과 회고

## 1. 시연 시나리오

### 1-1. 사전 확인 (1분)
```bash
python scripts/selfcheck.py --demo
```
기대: 모든 항목 `통과`, 마지막 `원본 무변경 (inbox·data·기준 문서) 통과`.

### 1-2. 사람이 오류를 넣는다
샘플은 01~04 정상, 05 는 원래부터 오류 사례(보완 7건). 01~04 중 한두 개를 PowerPoint 로 고치고 저장·닫기.

| 넣을 오류 (예) | 잡는 규칙 | 기대 판정 |
|---|---|---|
| 02 용접기: 투자수량 300 → 400 (필요 1500 − 현 1200 = 300 초과) | R-102 | 보완 + "300 이하여야" 문구 |
| 04 로봇: 선정 업체를 F사(2023 설립)로, 견적서 비교 '선정' 표시 이동 | R-107 | 보완 + "업력 5년 이상 업체 중 재선정" |
| 04 로봇: 선정 사유 줄 삭제 | R-106 | 보완 + 신생 업체 미선정 사유 예시 문구 |
| 03 GR: 현 장비 재원 슬라이드에서 '노후 수량' 줄 삭제 | R-314 | 보완 |
| 01 크레인: 투자유형을 노후교체로 | R-203·R-311~R-314 보완, R-201 판단 필요 | 보완 요청 |
| `samples/다른양식/` 파일을 inbox 로 복사 | R-100 | 변환본으로 점검 (원본 무변경) |

### 1-3. 점검 → 사람 확인 → 회의자료
1. `invest-reviewer 로 inbox 신청서 점검해줘` → `out/검토결과.html` 을 열어 넣은 오류가 설명되는지 확인
2. `out/검토결과.xlsx` ① 에서 판단 필요 행에 O (동의하는 것만)
3. `invest-meeting 으로 회의자료 만들어줘` → 표지에 통과 건만. 보류 건은 회의자료에 넣지 않고 실무자 보고로만 (실무자가 신청자에게 전달)
4. (안전장치 시연) Claude 에게 `inbox 02 를 고쳐줘` → 대화 세션이면 승인 창, 에이전트면 `[안전장치]` 차단 메시지

### 1-4. 실제 실행 기록 (2026-11-13, 사본 폴더)
- invest-reviewer 실제 실행: 신청서 6건(다른 양식 1건 포함) → 다른 양식 변환 통과(추가 0·누락 0·왕복 0), 5건 상정·1건(05) 보류, inbox SHA-256 전후 동일
- 변환 경계 사례 1건: 에이전트가 "견적 2곳 비교"의 2 를 견적 수 칸에 옮김 — 원문 글자라 검증은 통과, 스킬 규칙상 사람 판단 지점으로 기록
- 표지 결과(샘플 기준)가 업무 규칙의 표지 예시(정답셋 T1~T5)와 일치: Z1→Z2 위치 변경 / 용접기 수량·유형 변경 / GR 계획 外 / 로봇 계획 금액 초과 / A1 안벽 미신청

## 2. 사람이 확인한 지점과 이유

| 시점 | 사람이 한 일 | 이유 |
|---|---|---|
| 요구 정의 | 업무 흐름·검토 기준을 엑셀로 작성, 규칙 추가 지시 (유형별 필수 정보, 수량 관계, 투자경과 의미, 신생 업체 미선정) | 암묵지를 규칙으로 바꾸는 것은 업무 담당자만 가능 |
| 규칙 확정 | 수량 칸 정의 변경(현/필요/투자), 신생 업체 기준 5년 확정 | 임시값을 쓰면 에이전트 판정이 틀린 기준을 굳힘 |
| 테스트 방식 결정 | "샘플에 내가 오류를 넣고, reviewer 는 원본을 고치지 말고 엑셀/HTML 로 설명" | 점검기가 원본을 고치면 오류가 사라져 점검을 검증할 수 없음 |
| 산출 형태 결정 | 오류 설명을 엑셀 → HTML 로 | 읽는 사람(검토자) 기준. 승인 기록은 엑셀에 남김 |
| 양식 통일 범위 | "양식만 변경, 내용 변경은 안 됨" | 신청서 내용은 신청자 책임 — 자동 검증(추가·누락 0)으로 보장 |
| 판단 필요 승인 | 엑셀 검토자 확인 O | R-401: 서술 해석은 사람이 최종 책임 |
| 원본 수정 실행 | 수량 칸 변환 스크립트를 사용자가 터미널에서 직접 실행 | 백그라운드 세션은 훅이 에이전트로 보고 차단 → 사람만 원본을 바꿈 |

## 3. 회고

### 잘된 점
- **확정 규칙과 AI 판단의 분리**: 숫자·존재 여부는 스크립트, 서술 해석(R-201·R-301·R-322)만 에이전트. 에이전트가 스크립트 판정을 바꿀 수 없게 `judge` 가 거부 → 재현 가능한 판정
- **정답셋 우선**: 엑셀 T1~T6 을 먼저 테스트로 옮기고 구현 → 표지 문구까지 엑셀 예시와 일치
- **실제 에이전트로 검증**: 처음엔 AI 판단 단계를 사람이 대신 수행했으나, 이후 실제 에이전트를 사본 폴더에서 돌려 원본 보존·변환·전달을 확인

### 문제와 대응 (실제로 일어난 일)
| 문제 | 원인 | 대응 |
|---|---|---|
| 사용자가 고친 inbox 신청서를 덮어씀 | 샘플 생성기를 재실행하면서 기존 파일을 무조건 다시 씀 | 기존 파일 보존(`--force` 만 덮어씀) + `--force` 는 훅이 차단 + 메모리에 작업 방식 기록 |
| Claude 가 사용자 요청으로 inbox 를 직접 수정 | "원본 읽기 전용" 이 지침 문장뿐이었음 | 훅으로 강제 (에이전트 차단, 대화 세션은 승인) |
| 테스트가 inbox 상태에 따라 실패 | 샘플 판정 테스트가 사용자가 고칠 수 있는 inbox 를 읽음 | 임시 폴더에 고정 샘플을 만들어 검사 |
| 첨부 슬라이드 글자가 안 보임/빨간색 | 셀 글자 서식을 지워 표 스타일 색이 적용 | 원래 글자 서식(rPr) 복제 |
| 한글 깨짐 (콘솔·훅 메시지) | Windows 기본 cp949, `python -I` 가 PYTHONIOENCODING 무시 | 파일은 UTF-8 로, 훅은 UTF-8 바이트로 출력 |
| 훅 오탐: 사본 파일·상대경로를 원본으로 판단 | 파일 이름만 비교, 상대경로를 프로젝트 기준으로 계산 | 실제 경로·훅 입력의 cwd 로 판단, 회귀 테스트 추가 |
| 루트 재귀 삭제를 못 막음 | 옵션이 경로 앞에 오는 PowerShell 형태 누락 | 옵션 위치와 무관하게 대상 검사 |
| 대화형 승인이 백그라운드 세션에서 차단으로 동작 | 백그라운드 작업은 훅 입력에 에이전트로 표시 | 원본 변경은 사용자가 터미널에서 직접 실행 (명세에 한계로 기록) |
| 다른 플러그인 훅(qc-kit)이 `data/` 언급 명령을 차단 | 사용자 환경의 별도 플러그인 | 테스트 입력을 명령줄이 아닌 테스트 파일에 둠 |

### 남은 과제
- `config/기준값.json` 의 [확정 필요] 값(허용 금액 차이, 운용연수·회수기간 기준, 부 유형 필수 항목) 동료 합의
- 집행 이력(M-7 분할 신청) 실데이터 관리 여부 확인
- 이미지로 붙인 글자·표는 읽지 못함 → 경고만 표시 (OCR 미도입)
- 셸 검사는 문자열 기반 → 사후 지문 감지로 보완 중, 근본적으로는 OS 수준 쓰기 권한(읽기 전용 폴더)으로 강화 가능
